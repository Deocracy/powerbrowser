# Internal APIs Catalogue

D-96/D-97: `powerbrowser/shell/PowerBrowserAPI.sys.mjs` is the **only** file in
`powerbrowser/` permitted to reach a Firefox internal. Every row below is one
distinct occurrence of a forbidden pattern (`Services.*`, `Cc`/`Ci`/`Cr`/`Cu`,
XPCOM constructors, `AppConstants`, an unqualified `ChromeUtils.import*`,
actor registration, `nodePrincipal`, `fixupAndLoadURIString`, and (NG-039)
`wrappedJSObject`, `drawSnapshot`, `IOUtils`, `SessionStoreUtils`,
`ChromeUtils.generateQI`, the actor base classes and `gBrowser`) as
enumerated by `scripts/check-internals-boundary.sh`'s own
`FORBIDDEN_PATTERNS` array, run in `--catalogue` mode directly against
`PowerBrowserAPI.sys.mjs` (the one file the default `--quick`/full scan
excludes). The rule is written once in that script; this document is derived
from it, not maintained beside it — `check-internals-boundary.sh --catalogue`
fails on any occurrence with no matching row here, naming the uncatalogued
`file:line`. `GroupActorChild.sys.mjs` is the one other file with rows here: it
may carry only `wrappedJSObject` and `JSWindowActorChild`, each occurrence
catalogued (NG-039). Only a table row's File:Line cell counts; a `file:line`
cited in prose does not. The shell's own `gBrowser` stand-in definition
(`window.gBrowser = {` in `powerbrowser.js`) is the one exempt `gBrowser` line:
it defines an object and reads no Firefox internal.

One row = one touchpoint + why, the same discipline
`powerbrowser/endpoint-allowlist.json` already uses for network hosts.

**Append-only rule (Phase 27):** a new touchpoint is a new row appended at the
end of the Touchpoints table. New boundary code goes in an end-of-file section of
`PowerBrowserAPI.sys.mjs`; an existing line changes in place.
`scripts/verify-ng-040-internals-catalogue-lines.mjs --fix` runs after every edit
of the boundary file, and it never writes a row.

**Privileged-kind rule (Phase 27; store kinds, Phase 29):** a `webTab*` kind that
changes state outside a tab's own navigation, lifecycle or selection (permissions,
site data, Places writes, clipboard, stock pages) runs only from a widget event
handler and never gets a command id or a key-relay row. Every `case "webTab…"` arm
is classified in `scripts/verify-web-tab-bridge.mjs`, so an unclassified kind fails
there. Phase 27 adds no privileged kind. The same holds for store kinds
(`STORE_REQUEST_KINDS`, served by `handleStoreRequest`): a store kind that writes
Places or reads the clipboard is classed privileged, runs only from an event handler
in one of the two sanctioned chrome-bar files -- `address-bar/address-bar.tsx` (the
pill: Shift+Delete, paste, the bookmark star and its editor) or `chrome-bar-widget.tsx`
(the History submenu, the bookmarks toolbar and the Clear Recent History confirm,
Phase 33) -- through its same-named `ChromeStoreClient` method, never gets a command
id or a key row, and never enters `TAB_STORE_RELAY_KINDS`; a store kind that sends user input off the machine is
classed network and never enters the relay either. Every store kind is classified
in `scripts/verify-web-tab-bridge.mjs` rule 12. Phase 29 adds the first network
store kind, `searchSuggestions` (29-06), and the first privileged store kinds (29-09). Phase 33
adds the privileged `bookmarkPage`, `updateBookmark`, `removeBookmark` and `clearHistory`
and the read kinds `listClosedTabs` and `reopenClosedTab`. A store kind that changes only
window chrome state -- no Places write, no clipboard read, nothing sent off the machine -- is
classed `window-chrome` (Phase 33 plan 05, D-14b/N1). It is the one class a command id may
reach: the MENU-03 `full-screen` id, which the Full Screen row and its Actions twin both run,
toggles `fullScreen`, while a privileged kind never takes a command id. A window-chrome kind
is still never relayed and is called only from the `chrome-bar-widget.tsx` handler that the
command's opener runs. `fullScreen` is the first.
Phase 35 (35-03, D-09) adds `webTabContextMenuAction`, the page context menu's pick: it is
classed privileged, listed in `PRIVILEGED_WEB_TAB_KINDS` with its reason, and sent only from
`theia/extensions/chrome-bar/src/browser/page-context-menu.ts`. Its payload names the tab, a
single-use menu id and a row chrome offered for that menu; every target is read from the
captured `contentData`, never from the payload.

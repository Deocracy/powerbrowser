# Contributing to this organization's projects

Thank you for helping. This guide applies to every repository in the organization unless the repository has its own version.

## Before you start

- **A question or an idea to discuss:** start a discussion where the repository provides Discussions. Otherwise, open an issue.
- **A bug:** open an issue, or use the bug report form where the repository has one. Include the version, the operating system and the steps that show the problem.
- **A feature:** open an issue, or use the feature request form where the repository has one. Describe the problem before the change.
- **A security problem:** do not use issues or discussions. Follow the organization's SECURITY.md.

## Proposing a change

1. Fork the repository and make your change on a branch of your fork.
2. Keep each pull request to one change, and say what it does and why.
3. Pull requests from forks need a maintainer's approval before any workflow runs. This protects the project's secrets, and it is not a judgment about your work.
4. A maintainer reviews the pull request. Expect questions; they are a request for more facts, not a verdict.

## Labels

Maintainers apply labels to triage issues and pull requests. Labels describe the area, the install format and the state of the report. Contributors do not need to set them.

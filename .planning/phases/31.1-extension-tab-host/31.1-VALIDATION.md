## Sampling Rate

- **After every task commit:** `scripts/verify-platform.sh --quick`.
  - Stage new `patches/` and `scripts/` files first, because the brand scan reads `git ls-files`.
  - After any `PowerBrowserAPI.sys.mjs` edit, run `node scripts/verify-ng-040-internals-catalogue-lines.mjs --fix`, then `bash scripts/check-internals-boundary.sh --catalogue`.
  - After any change to `patches/050-*.patch`, run `bash scripts/apply-patches.sh --self-test`, `bash scripts/check-patch-surface.sh` (with `--self-test` and `--self-test-brand`) and `node scripts/verify-ext-tab-host-patch-guards.mjs --self-test`. If 050 changes after 31.1-01 Task 3, that task's steps 1-6 (reset, replay, build, stamp) run again before any live row.
- **After every task that lands live scenarios** (31.1-02 Tasks 1-3, 31.1-04 Tasks 1-3; 31.1-02 Task 1 runs the existing `gui01-single-shell-window` and `gui02-web-tab-live` rows, the later tasks the new suite): run the stamp check, then `node scripts/verify-ext-tab-host-live.mjs --scenario <that task's scenarios>` and `--self-test`. The binary exists from 31.1-01 onward, so no live row is ever pending, and no task finishes with one pending.
- **31.1-03** is static only: `--quick` with the scope gate and its self-test.
- **Phase close (31.1-04 Task 3):** a Theia build, then the default live run (14 scenarios), the live `--self-test`, the `gui01-single-shell-window`, `gui01-browser-close-does-not-quit` and `gui02-web-tab-live` regression rows, and `--quick`. All of them must be green.
- **Before `/gsd-verify-work`:** the full `scripts/verify-platform.sh` is green.
- **Max feedback latency:** about 90 seconds (quick).

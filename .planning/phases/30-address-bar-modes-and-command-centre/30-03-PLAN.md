<objective>
Contribute the four local modes, Tabs, Bookmarks, History and Actions, through `AddressBarModeContribution`, with their zero-query lists, filtered lists, trailing search row and copy. After this plan the modes dropdown lists every SMODE-01 entry except Command centre (30-04).

Purpose: SMODE-01's Bookmarks, Tabs, History and Actions rows, D-11's Actions scope, and Organising's D-02 default (Tabs) becoming live. Research found that `searchPlaces` cannot serve the zero-query lists (it has no restrict field and returns nothing for empty text), so chrome gains a restricted reader behind the same kind (30-RESEARCH Pattern 6, Pitfall 8).

Decided (autonomous, recommended; recorded): Tabs reads the shell's own web tabs (exact and unbounded) rather than the backend tab RPC, which clamps to 8 and reads the store; its most-recently-used order is an in-memory list the Tabs mode records from `ApplicationShell.onDidChangeCurrentWidget` (30-RESEARCH A7; the mode subscribes itself, so it never injects `AddressBar` and no injection cycle forms); tabs never activated this session follow in tab-strip order. Bookmarks and History use one recency order whether or not text is typed. Actions lists only visible and enabled commands, as the stock command palette does; `CHROME_BAR_FOCUS_ADDRESS` stays labelless and outside the category (it is pinned labelless, and running it from the pill would only refocus the pill), so D-11's "focus address" example is not listed.

Output: four contributions, local-mode rendering in `AddressBar`, `searchPlacesRestricted` chrome-side, the optional `restrict` client argument, the `Browser` command category, copy, live scenario `local-modes` with three plants.

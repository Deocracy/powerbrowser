<objective>
Let the user pick the default engine among the engines `configuration.toml` supplies (BAR-04 UI half): a `browser.defaultSearchEngine` setting whose options come from chrome, the effective engine carried on every resolve request, and a placeholder that names the engine actually in use. Then prove on the packaged build, where `policies.json` exists, that the bar offers exactly the configured engines with the first as default.

Decided (autonomous, recommended; 29-RESEARCH Alternatives and Open Question 2): there is no default-engine write kind. The setting's value rides each `resolveTypedAddress` request as `engineName`, and chrome accepts only a name in the bar's engine set. A preference listener is not a widget event handler, so a write kind there would break the privileged-kind rule. This narrows 29-UI-SPEC's "the setting changes it only through a PowerBrowserAPI kind" to "validated by the kind on every request"; Gecko's own default is never changed by the setting.

Output: the `listSearchEngines` kind and client method, the setting with its runtime options, the engine-naming placeholder, live scenario `default-engine`, `scripts/verify-search-engines-packaged.mjs` and its registry row.
</objective>

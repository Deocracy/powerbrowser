## How edits reach the live binary

Chrome-side files reach the binary without a Gecko rebuild:
`objdir/dist/bin/browser/chrome/browser/content/powerbrowser/*` are symlinks into
`upstream/powerbrowser/shell/`, `upstream/powerbrowser` links to
`../powerbrowser`, and the live harness sets `MOZ_PURGE_CACHES=1`
(`scripts/lib/pb-live-probe.mjs:44`), so the next live session runs the edited
`powerbrowser/shell/*.js` or `*.sys.mjs`, not a startup-cached copy. A Gecko
rebuild is needed only when `powerbrowser/shell/jar.mn` changes, a new chrome
file is added, or `patches/050-extension-tab-host.patch` is regenerated (by this
phase or by 31.1 after the binary was last built). In that case run
`scripts/apply-patches.sh`, then `MOZCONFIG=../.mozconfig ./mach build` from
`upstream/` inside `nix develop .#firefox`, before any live run. Theia-side
edits need only the Theia build in the standing live rule.

This plan: it edits no chrome-side file and no patch.
`endpoint-allowlist.json` is read by the check scripts (`verify-endpoints.sh`,
`verify-webextensions.mjs`), not loaded by the binary, so no Gecko rebuild. The
phase close runs on the same binary 38-01..38-04 ran on.

<objective>
Gap closure discovered by 38-06 (worker-wall), fix approved by the owner (Chris, 2026-11-01).

@theia/plugin-ext gives each webview its own origin from `{{uuid}}.webview.{{hostname}}`, where
the frontend substitutes `location.host`. In PowerBrowser that is `127.0.0.1:<port>`, so the
origin is `<uuid>.webview.127.0.0.1:<port>`: glibc refuses it and Gecko resolves only `*.localhost`
itself. No webview, and no webview service worker, ever loads.

Theia facts that shape the fix (read from the installed 1.76.0 package):

- The browser-target pattern comes from `THEIA_WEBVIEW_EXTERNAL_ENDPOINT` (backend process.env,
  read by the frontend through EnvVariablesServer). It has only `{{uuid}}` and `{{hostname}}`
  placeholders; the port is never appended, it arrives inside `{{hostname}}`.
- The backend serves `/webview/*` through `vhost(regex)`, and vhost strips the port before
  matching. A pattern with a literal port therefore never matches, and a portless literal stops
  `allowWsUpgrade` refusing webview-origin websockets (it tests `URL(origin).host`, port included).
- TheiaService spawns on `--port 0` the first time, so the port is not known when the
  environment is built.
- Any pattern other than the default makes the frontend raise a warning toast that prints the
  raw pattern: an internal identifier in user-facing text.

So the endpoint cannot be a literal environment value. The fix keeps Theia's default pattern and
changes only the hostname the frontend substitutes into it.
</objective>

  <action>
  - token-gate `src/common/webview-host.ts`: the loopback name `localhost` and `isWebviewHost(host)`.
  - tab-uris: rebind `WebviewEnvironment` to a subclass whose `doInit` substitutes

    pattern, so no warning toast; the backend's default regex already matches the new host for
    vhost and for the websocket refusal.
  - TheiaService pins `THEIA_WEBVIEW_EXTERNAL_ENDPOINT` to Theia's default pattern, so an inherited
    value from the launching shell cannot move the origin away from what the frontend, the
    hidden-origins pref and the gate assume.
  - Token gate: a request whose Host is a webview host may GET or HEAD only `/webview/<file>.html|js`
    (Theia's static webview shell). Everything else on that host is refused as before. Resources
    reach the webview through its service worker and the main frame's authenticated RPC, not
    HTTP. The token cookie is host-only on 127.0.0.1 and SameSite=Lax, so it is neither sent to
    the webview origin nor attached to the webview's cross-site requests to 127.0.0.1.
  </action>
</task>

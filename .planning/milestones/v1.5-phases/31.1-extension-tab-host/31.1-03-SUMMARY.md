## Deviations from Plan

1. **One commit for both tasks.** Tasks 1 and 2 build one file. Making an intermediate Task 1 state would have meant writing and testing a second version of the gate for no gain. Every task verify command ran on the final file, and the commit message lists both families.
2. **Stand-in gate touched outside `files_modified`.** The plan's `host:` claims must reuse the stand-in gate's literal parser, which was not exported. The change is export-only: `deriveImplemented` is exported, `resolve` is imported, and `main` / `selfTest` run only when the file is the entry point. `--self-test` and the default run are unchanged, and both were re-run green.
3. **New-loop plant placed in the pristine bytes, not the post-image.** The plan says "a new loop added to a staged ext-tabs.js post-image". Sites are derived from the pristine bytes by design (task 1, step 3), so a loop present only in the post-image is never seen. The plant therefore goes into the pristine override, which is what an upstream rebase does. The red line still names the file and line.
4. **Acceptance grep count.** `grep -n 'ext-tab-host-scope|' scripts/verify-platform.sh` prints one line (the quick row, line 3675). The self-test row is labelled `ext-tab-host-scope-self-test`, so it does not match the `|` in the pattern. Both rows exist; the same grep shape was recorded in 31.1-02 Deviation 10.
5. **Commit trailer.** The plan says Opus 5.5. The orchestrator's rule and the session attribution say Haiku 5.5, so the commit ends with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.
6. **Per-plan commit ledger (protocol 0c) not written.** The `commits:` field is measured with `git rev-list --count 0c24030..HEAD` against the recorded base, not from a ledger file.

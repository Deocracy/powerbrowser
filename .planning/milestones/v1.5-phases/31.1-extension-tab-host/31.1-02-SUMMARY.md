## Deviations from Plan

1. **Co-author trailer.** The plan's commit template says Opus 5.5. The orchestrator and the session's attribution rule say Haiku 5.5, so every commit here ends with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.
2. **No `--fix`.** The plan says to run `verify-ng-040-internals-catalogue-lines.mjs --fix` after each boundary edit. The orchestrator forbids it, so drifted rows were remapped by line diff and checked. A first remap pass skipped rows whose first cell held a second code span; it was discarded and the catalogue was rebuilt from the committed text, so no row was left stale.
3. **STATE.md and ROADMAP.md not edited** (orchestrator rule). The plan's state step was skipped.
4. **Shell error-contract fixture (Rule 3, blocking).** `scripts/verify-shell-error-contract.mjs` runs `powerbrowser.js` against a fake `ChromeUtils.importESModule` that returned only `PowerBrowserAPI`. The new bootstrap line `PowerBrowserTabHost.install(...)` threw, so `--quick` went red. The fake now also returns a `PowerBrowserTabHost` whose `install()` yields a stub accessor. Its assertions are unchanged, and its self-test still passes. `verify-ng-037-core-close-quits.mjs` and `verify-start-path-recovery.mjs` also load `powerbrowser.js` and both pass. This file was not in the plan's `files_modified`.
5. **Gate receiver rule, own fix.** The first derivation picked up `classList`, `append`, `setAttribute` and similar names because a binding lookahead accepted `&&`, so `let { node } = window.gBrowser && this.widget.forWindow(window)` bound `node` as a gBrowser receiver. The lookahead now accepts only a statement end. Derived sets were printed and checked after the change.
6. **focus-follow scenario restructured (plan wording not achievable as written).** The plan puts B beside A and then makes A current before the page focus on B. In this build, after `addWidget` split, Theia's main-area current stayed on B through four routes, each measured: `shell.activateWidget(A)`, `mainPanel`'s tab bar `currentTitle = A`, `widget.activate()`, and `widget.node.focus()`. The scenario now puts B beside A (B is current, Lumino makes an added widget current), and page focus goes to A. Its assertion is that A is the active tab. The diagnostic showed that page focus also moves Theia's current to A, so this layout does not isolate page focus from Theia's current. The plan's premise that "Theia's current stays A" is therefore not demonstrated in this build. The `focus-ignored` plant pins the selection to B, the unfocused overlay, to match. Open item for 31.1-03/04 to review.
7. **Harness corrections (test code only; no product change).** (a) The query scenario checks for a Theia tab before the zero-tab count, so the plant's failure names its drift. (b) The sender and webrequest scenarios wait for the content-script report or the network event rather than webNavigation's commit, which the tracker withholds when it cannot name a tab, so the plants name their drift. (c) The favicon arrives as a `data:image/png;base64,` URL (Firefox re-encodes it), so the check accepts that form. (d) Three selection plants originally compared against `tabs[0]` at zero tabs and reported "did not land"; each now records the replaced getter and checks that it changed. (e) The popup-type plant reads the app window the way ext-tabs-base.js does (`treeOwner.QueryInterface(nsIInterfaceRequestor).getInterface(nsIAppWindow)`), after a direct `QueryInterface(nsIAppWindow)` threw.
8. **Product changes beyond the plan's explicit text.** `attachProgress` also sets the overlay's `busy` attribute from the top-level network state and `label` from the page title, as the plan described, and `detachProgress` removes the listeners on drop. Both are in the plan's Task 3 description; they are listed here because the plan's shape for them was an outline.
9. **swapBrowsers behaviour change.** Before the host, `swapBrowsers` on an overlay skipped silently, because the receiver was null. With the host it throws a TypeError. No shell code reaches it. Recorded as an open item (see DELIBERATELY_ABSENT).
10. **Acceptance grep count.** The plan expects `grep -n 'ext-tab-host-live|' scripts/verify-platform.sh` to print two lines. The default row is `ext-tab-host-live|...` and the self-test row is `ext-tab-host-live-self-test|...`, so the pattern matches one line. Both rows exist (lines 5052 and 5053).
11. **Not run here.** `gui01-browser-close-does-not-quit` and the phase-close regression set belong to 31.1-04. Patch 050 and the build were not touched.

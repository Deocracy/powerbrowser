**Boundary file: the end-of-file section.** Add a section headed `// Phase 31.1: the extension tab host.`, written in the Phase 27 header style. It holds:
- `tabHosts`, a WeakMap from chrome window to the host record. The record is `{ strip, theiaBrowser, byBrowser, byTabId, selected, progressListeners }`.
- `export const PowerBrowserTabHost = Object.freeze({ install(win, theiaBrowser) { … } })`. `install`:
  - creates the strip with `win.document.createXULElement("hbox")`, id `powerbrowser-tab-host`, `hidden` set, appended to the document element;
  - defines the shim on one line beginning `win.gBrowserInit = {`, with members `delayedStartupFinished: true`, `getTabToAdopt()` returning null and `isAdoptingTab()` returning false;
  - throws on a second install for the same window;
  - returns a frozen accessor object. Its members are `tabs()` (the strip's children as an array), `selectedTab()`, `selectedBrowser()`, `currentURI()`, `getTabForBrowser(b)` (host nodes only, otherwise null), `getBrowserForTab(t)`, `isTab(t)`, `getIcon(t)`, `setIcon(t, url)`, `getTabSharingState()` (camera, microphone and screen all undefined, as 002a did), `addTabsProgressListener(l)`, `removeTabsProgressListener(l)` and `refuse(action)`.
- `setIcon` stores a string URL on a host node as `image` and dispatches `TabAttrModified` with `changed: ["image"]`. Anything else is ignored.
- `refuse(action)` throws an Error with a plain sentence such as "PowerBrowser cannot open a tab for an extension yet." The messages carry no identifier, pref, port or internal name, and `verify-shell-error-copy.mjs` stays green.

**`tabHostAddTab(win, tabId, browser)`.**
- D-06 guard: it returns without creating a node unless a host exists for the window and `browser.getAttribute("messagemanagergroup") === "browsers"`.
- Node: it creates a `createXULElement("hbox")` node (CONTEXT discretion: a plain XUL element, proven live in 002a `tabhost.js:132-148`) with the 002a field set: `linkedBrowser`, `linkedPanel` (a per-host counter string), `pinned`, `hidden`, `multiselected`, `muted`, `muteReason`, `soundPlaying`, `undiscardable`, `openerTab`, `group`, `splitview`, `userContextId`, `lastAccessed`, `label`, `image`, `successor` and `closing`. It adds a `_tPos` getter (the index in the strip) and a `selected` getter. It has no `toggleMuteAudio`: mute is Phase 32's, and an extension mute write fails loudly as a TypeError.
- Order: it appends the node to the strip, maps it by browser and by tab id, and selects it if nothing is selected. It then dispatches `TabOpen` with detail `{ adoptedTab: null }` as a bubbling `win.CustomEvent`, followed by `TabSelect` with `{ previousTab: null }` when this node became the selection. If `activeTabByFrame` already names this `tabId` for the frame, it then selects that node (the `webTabActivated` arm may have run before the open).

**`tabHostDropTab(win, browser)`.**
- It sets `closing = true` and dispatches `TabClose` with `{ adoptedBy: null }` while the node is still in the strip; `TabTracker.getId` may need `parentNode`.
- It then removes the node from the strip and both maps.
- If the node was selected, it selects, in order of preference: the tab `activeTabByFrame` names, if that tab is live; else the tab now at the same index; else the previous tab; else null. For a non-null choice it dispatches `TabSelect` with `{ previousTab: dropped }`. The dropped node is `closing`, so the tracker reads no id from it (`ext-browser.js:680-683`).

**`selectNode(host, node)`.** It is a no-op if the node is already selected. Otherwise it sets the selection, updates `lastAccessed` and dispatches `TabSelect` with `{ previousTab }`.

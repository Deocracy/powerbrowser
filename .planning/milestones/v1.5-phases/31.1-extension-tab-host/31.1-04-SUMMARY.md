## Deviations from Plan

1. **One commit for Tasks 1 and 2.** Both edit `scripts/verify-ext-tab-host-live.mjs`. Splitting the file would have meant committing an intermediate state that had no proof of its own. Every task verify command ran on the final file before the commit.
2. **Commit trailer.** The plan says Opus 5.5. The orchestrator's rule and the session attribution say Haiku 5.5, so the commit ends with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.
3. **Probe fixture extended for every session.** The fixture now has `browser_action`, `page_action` (show_matches `<all_urls>`), a `commands` entry, a `tabs.onZoomChange` listener, a `started` report and `page.html`. Every scenario therefore runs the zoom loop and the page_action start path. The nine 31.1-02 scenarios were re-run on this fixture in the gate and stay green.
4. **Fixture defect found by the recorder (harness only).** The first adversarial run failed with 12 recorded `DataCloneError: Response object could not be cloned @ ExtensionChild.sys.mjs:872`. The probe's listeners returned the `fetch` promise from `post()`, so the framework tried to clone the `Response`. The same shape was in the 31.1-02 fixture, where it was invisible because no scenario read the framework error channel. `post()` now returns undefined. This is not a product defect; no product code changed.
5. **Recorder control is delivered asynchronously.** The first recorder read the captured list synchronously and reported `BROKEN INSTRUMENT` with its control missing. `installErrorRecorder` now polls for up to 2 s for the control to arrive, then removes it before any absence counts. The positive control is still required in every session.
6. **`bad-selected-tab` is applied late.** The plan's case is a reload with a web tab open, so the scenario opens `/a` and then applies the planted `selectedTab` override. A plant applied before install would test a different path.
7. **`selected-not-visible` plants the first web tab.** The override returns `gBrowser.tabs[0]`, which is `/a` because `/a` is opened first. The plant is a `body` plant (applied before the scenario), as `stale-active` is.
8. **Shell keyset is informational.** The plan's text says the shell's document has the same keyset. The gate records `shell keyset present true` but does not assert it, because Phase 38 owns the shell's command surface. G6 skips only the shell's sidebar shortcut update; the keyset is created in both windows.
9. **Lock precondition, reported for the orchestrator to confirm.** The Task 3 precondition asks for `.planning/milestone.lock` to be absent or to name phase `31.1`. It reads `"phase": "31"`, with session `claude-code-session-id-b4633832-...` (this orchestrator's session) and pid 3323553, which is not running. No other process held the tree. The lock was not edited, and the gate proceeded on the same reasoning as 31.1-01 Deviation 2. If the orchestrator wants the literal precondition, the lock needs a decision before this phase is marked closed.
10. **Self-test PASS line.** The plan's acceptance says the `--self-test` PASS line lists every plant. The script prints one `ok plant <name> -> red, naming ...` line per plant and then a summary PASS line; the table above is taken from those lines.
11. **Acceptance grep counts.** The registry rows `ext-tab-host-live` and `ext-tab-host-live-self-test` exist unchanged (`scripts/verify-platform.sh` lines 5060-5061). No row was added, because the default run already executes every scenario the script defines.
12. **Focus-follow layout (31.1-02 Deviation 6) stands.** Lumino moves Theia's current to A with the DOM focus in this build, so `focus-follow` does not isolate page focus from Theia's current. Not changed here.

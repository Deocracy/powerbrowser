**Guard table.** `GUARDS` holds G1-G8 from Task 1, and it is the gate's one hand-kept table; each row carries its reason. A row gives the target path, the anchor (the trimmed upstream line the guard replaces or sits beside), the mode, the guard regex or regexes, and the `site` (the `Outer.inner` definition the guard must sit in):

**Guard checks.** A guard holds when all four of these hold:
- (i) The target file has a hunk containing the anchor in the stated role.
- (ii) Every guard regex matches a `+` line in that change block.
- (iii) **Site (W2).** The gate builds the post-image with `git apply` of the patch in a `mktemp -d` git repository seeded with the pristine bytes of the patch's target files (a failed apply is a broken instrument), locates each guard `+` line in the post-image by its hunk's new-file line numbers, and derives the line's site by an indentation-ancestor walk. From the line, walk upward over non-blank, non-comment lines, taking each line whose indentation is smaller than the last line taken. The first two taken lines that define a bare identifier give the site, outer name first. A definition is a method (optional `async`, `static`, `get`, `set` or generator `*` prefix, then `name(…) {`), `function name(`, `class Name`, or `name =`/`name:` (optional `let`, `const` or `var`) whose value starts a function, arrow, class or `new` expression. A name reached through a member expression, such as `this.pageAction = class`, is not a bare identifier and is skipped, as are the keywords `if`, `for`, `while`, `switch` and `catch`. A line starting `*` followed by an identifier and `(` is a generator method, not a comment continuation. The derived site must equal the row's `site`. Git's hunk-header funcname is not used: for an indented method it is the class line, so it cannot tell two methods of one class apart.
- (iv) The anchor occurs exactly once in the pristine file, and its site (for `after-anchor`, the site of the pristine line directly after the anchor) equals the row's `site`.

**Failure kinds,** each naming the guard id and file: MISSING (no matching `+` line at the anchor), WEAKENED (the anchor is replaced by a `+` line the regex rejects), MISPLACED (the shape matches but the guard line's derived site differs from the row's `site`, naming both), ANCHOR DRIFT (the anchor occurs zero or two or more times upstream, or sits in a different site: a rebase moved it, so regenerate), and BROKEN INSTRUMENT (the patch is unreadable, the patch has zero hunks, a `git show` fails, or the scratch apply fails).

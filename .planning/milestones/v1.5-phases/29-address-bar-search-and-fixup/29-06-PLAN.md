<objective>
Show the engine's search suggestions while typing (BAR-03; on by default with a setting to turn them off, CONTEXT locked decision 3) and the one-off engine strip that searches with another engine this time only (BAR-05).

Purpose: ROADMAP success criterion 2's suggestions and one-off clauses. Suggestions are anonymous chrome-side requests (`SearchSuggestionController`, `LOAD_ANONYMOUS`) and are never made for text chrome resolves as an address (29-RESEARCH Pattern 3).

Decided (autonomous, recommended): a query in flight is cancelled in the frame (its reply is dropped by sequence on commit, Esc and blur), and the chrome-side request is stopped by the next fetch on the same per-frame controller; no stop kind is added. Enter on a suggestion commits its text through the same resolve path as typed text, so a suggestion that is itself an address visits it.

Decided (autonomous, recommended): a plant "suggestions sent for URL-shaped text" was considered and rejected. Chrome re-resolves the text and refuses, so the plant cannot be built from the page realm; it would need a product-side switch that turns chrome's address fence off, and no product code may exist only so a test can disable a security check. The `suggestions` scenario therefore asserts chrome's fence directly (a page-realm `searchSuggestions('localhost:4000')` returns `[]` with no request logged) after the `hel` positive control proves the request log sees this engine's suggest GETs in the same session, and the `setting-ignored` plant proves that the scenario's request-absence assertions can go red.

Output: the `searchSuggestions` kind (class network), `browser.searchSuggestions`, engine rows, the one-off strip, live scenarios `suggestions` and `one-off`.
</objective>

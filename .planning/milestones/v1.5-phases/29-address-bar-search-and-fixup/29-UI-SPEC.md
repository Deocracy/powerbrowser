# Phase 29 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** This phase extends the chrome bar contracted in 13-UI-SPEC and 27-UI-SPEC. Tokens,
geometry, type, colour, focus ring, motion, the layer policy and the `{App}` copy rule are all
inherited and are not re-specified unless they change. It adds the following, for BAR-01..14:

- search fallback, with a placeholder that names the engine
- development-address fixup
- the heuristic first row
- engine suggestion rows
- history, bookmark and open-tab rows with favicons and type icons
- the one-off engine strip
- inline autofill
- the switch-to-tab row
- new-tab targets (Alt+Enter, Ctrl+click, middle-click)
- Shift+Del removal of a history row
- the pill context menu (Cut, Copy, Paste, Paste & Go)
- two settings: search suggestions on/off and the default engine
- select-all on the first click
- the IME guard
- typed text kept per tab
- dropping a link or text on the pill
- removal of the two remaining brand literals in chrome-bar copy

Hard rules that bind every row below:

- Never fork or patch Theia core. All UI is `@powerbrowser/chrome-bar` composition.
- Firefox internals are reached only through `PowerBrowserAPI.sys.mjs`.
- No custom browser chrome beyond the chrome bar itself.
- No internal identifier in user-facing text.
- The product name and engine names come from configuration and engine data, never from a literal.
- The pill writes to Places only through `PowerBrowserAPI`, never through raw SQL.
- No clipboard read without an explicit user gesture.

**Phase 30 boundary.** The modes dropdown, the mode chip and the move of the pill into
`address-bar/` belong to Phase 30. This phase adds nothing to the left of the lock glyph. Nothing
it adds may assume that the lock, or the input, is the pill's first child. Phase 30 inserts its
mode button as the pill's leftmost element (FEATURES SMODE-03), and that change must not require
any rework of this phase's code.

Mode: `/gsd-autonomous` (Chris's standing nonstop instruction). Every choice not fixed upstream
is marked **Decided (autonomous, recommended)**. Each one follows Firefox where Firefox has an
answer, and is consistent with the chrome-bar tokens and the sketch findings.

## Spacing Scale

Inherited unchanged. All values are multiples of 4, except the inherited 12px `md-gap` step.

| Token | Value | Usage in Phase 29 |
|-------|-------|-------------------|
| xs | 4px | Dropdown top offset below the pill (unchanged); gap between one-off buttons |
| sm | 8px | Gap between a row's icon, title, caption and trailing marker; one-off strip top padding; footer top margin (unchanged) |
| md-gap | 12px | Row horizontal padding (unchanged); pill horizontal padding (unchanged) |
| md | 16px | Dropdown padding (unchanged); row icon slot and type-icon slot are 16×16 |
| xl | 32px | Row height (now fixed, see below); one-off button hit area 32×32 |
| lg / 2xl / 3xl | 24 / 48 / 64px | Not used |

**Changed geometry (Decided, autonomous, recommended).** Rows become **single-line, 32px tall**,
as in Firefox's result rows. The order inside a row is: icon slot 16px, title, caption, then the
trailing type marker, separated by 8px. Today's rows stack the title and caption with a 4px gap,
which makes each row about 43px. At the new 10-row cap that would make the panel about 430px of
rows, so the stacked layout is retired. Within a row the caption truncates first and the title
keeps at least 40% of the row width.

Dropdown height: `max-height: min(432px, calc(100vh - <top> - 8px))`, with `overflow-y: auto`.
432px holds 10 rows (320), the padding (32), the one-off strip (8 + 32), the footer (8 + 18) and
rounding. The 304px cap from 13-UI-SPEC is replaced.

Exceptions: none new.

## Copywriting Contract

Inherited rules:

- No internal identifier in user-facing text: no pref key, kind name, engine id, port, timeout or raw exception.
- `{App}` is `appSubject()` from `chrome-bar-copy.ts`: the configured `applicationName`, or "The browser" when it is empty.
- `{engine}` is the engine's display `name` from `SearchService`, read at render time. No engine name or engine URL is ever written in Theia source.
- Every error ends with a next step that is a real affordance on screen.
- All new strings live in the `CHROME_BAR_COPY` object, so `verify-shell-error-copy.mjs` pins them by set equality.

| Element | Copy |
|---------|------|
| Primary CTA | **Enter** on the heuristic row. Its caption names the action it performs now: **"Search with {engine}"** or **"Visit"**. |
| Placeholder and input `aria-label` | **"Search with {engine} or enter address"**. Before the engine list arrives, or when there is no engine: **"Search or enter address"** (the existing string) |
| Heuristic row, search | Title: the typed text. Caption: **"Search with {engine}"** |
| Heuristic row, address or autofill | Title: the address that will load. Caption: **"Visit"** |
| Engine suggestion row | Title: the suggestion. Caption: **"Search with {engine}"** |
| History or bookmark row | Title: the page title, or the address when the title is empty. Caption: the address |
| Open-tab row | Title: the tab title. Caption: the address. Trailing caption: **"Switch to Tab"** |
| One-off strip label | **"This time, search with:"** |
| One-off button | Tooltip **"{engine}"**. `aria-label` **"Search with {engine}"** |
| Footer hint | **"Enter opens · Alt+Enter opens in a new tab · Esc closes suggestions"**. This replaces "Enter opens the address · Esc closes suggestions". |
| Commit failure row | **"{App} couldn't open that address. Press Enter to try again."** This replaces the literal at `chrome-bar-widget.tsx:1041`. |
| Suggestions failure row | **"{App} couldn't load suggestions. Press Enter to go to what you typed."** This replaces the literal at `chrome-bar-widget.tsx:1047`. It is shown only when the heuristic row itself could not be computed. |
| No-search row (no engine, or search could not start) | **"{App} can't search right now. Type a full address, such as https://example.com, and press Enter."** |
| Shift+Del failure row | **"{App} couldn't remove that page from your history. Press Shift+Delete to try again."** |
| Paste & Go failure row | **"{App} couldn't read the clipboard. Press Ctrl+V to paste, then press Enter."** |
| Context menu items | **"Cut"**, **"Copy"**, **"Paste"**, **"Paste & Go"**, separator, **"Select All"** |
| Setting: search suggestions | Shown as "Browser › Search Suggestions". Description: **"Show suggestions from your search engine while you type in the address bar. What you type is sent to the search engine."** |
| Setting: default engine | Shown as "Browser › Default Search Engine". Description: **"The search engine the address bar uses when what you type is not an address."** Option labels are the engine names. |
| Empty state | Empty pill text opens no dropdown: there is no list to show, and top sites are deferred. The old "No suggestions" row and its caption are **retired**, because non-empty text always produces a heuristic row. |
| Destructive confirmation | **Shift+Delete on a history row** removes the page from history immediately, with no confirmation and no undo (Firefox parity). It is accepted only on rows whose source is history (Pitfall 11). |

Settings keys follow the 27-UI-SPEC rule of a brand-neutral `browser.` prefix:

- `browser.searchSuggestions`: boolean, default `true`, User scope.
- `browser.defaultSearchEngine`: string, default `""`, User scope. `""` means the default that `configuration.toml` supplies. Its `enum` and `enumItemLabels` are filled at runtime from the engine list through `updateSchemaProperty`.

**Decided (autonomous, recommended):** both keys are User scope only, so a workspace settings file
cannot redirect search. Suggestions are on by default (Chris's ruling, 2026-10-20). The default
engine's initial value comes from `policies.json` `SearchEngines`. The setting changes it only
through a `PowerBrowserAPI` kind, which accepts only a name that is in the visible engine list.

`aria-keyshortcuts` and tooltip shortcut text come from the derived shortcut table, never from
`KeybindingRegistry` (27-UI-SPEC rule).

## Interaction Contract (BAR-01..14)

### Pill composition (left to right)

| Order | Element |
|-------|---------|
| *(Phase 30: mode button)* | Not in this phase |
| 1 | Lock glyph (unchanged) |
| 2 | Input, which carries `role="combobox"`, `aria-expanded`, `aria-controls` (the dropdown id), `aria-autocomplete="both"`, and `aria-activedescendant` pointing at the highlighted row |

The bar order outside the pill is unchanged from 27-UI-SPEC.

### Typing, resolving and Enter (BAR-01, BAR-02, BAR-13)

- **One resolve path.** Typed text goes to the single `resolveTypedAddress` kind: URI fixup, then the engine submission, then the http(s) wall applied to the result. It replaces `typedAddressTargetOf`.
- These open as addresses: `localhost`, `localhost:4000`, `host:port`, IPv4, `[::1]:8080`, any scheme'd http(s) URL, and dotted hosts.
- Single words follow Firefox's fixup rule for single words, and otherwise search the default engine.
- A resolution to a non-http(s) scheme (`javascript:`, `file:`, `chrome:`, `about:`) never loads. It shows the commit failure row.
- **Heuristic first row.** Whenever the text is non-empty, the dropdown's first row is the heuristic row ("Search with {engine}" or "Visit"). It is **highlighted by default**, so Enter does what it says. This is a change from today's `highlightIndex = -1`.
- Arrow keys move off the heuristic row. Enter on another row commits that row.
- **Ctrl+Enter** completes a bare `name` to `www.name.com` and opens it in the current tab. Text that already has a dot, a port, a scheme or a space behaves as plain Enter. **Decided (autonomous, recommended):** Ctrl+Shift+Enter (`.net`) and Shift+Enter (new window) are not added.
- After a search, the pill shows the results page's address. Showing the search terms instead is deferred.

### Suggestions (BAR-03, BAR-11)

- **Sources and order, Decided (autonomous, recommended) from Firefox's `showSearchSuggestionsFirst`:**
  1. The heuristic row.
  2. Up to **4** engine suggestions.
  3. Open-tab, bookmark and history rows, up to **5**, in the existing merge order: open tabs first, then Places, deduplicated by URL.
- The cap is **10 rows** in total. A URL that is open in a tab shows only as its open-tab row.
- **No engine request** is made when the heuristic row is "Visit". URL-shaped text, `localhost` and private addresses are never sent to the engine.
- No engine request is made while the setting is off, or during IME composition.
- Engine suggestions use the existing 150 ms debounce. A query in flight is cancelled on commit, on Esc and on blur.
- **Arrival:** rows that arrive late are inserted without moving the highlight. The highlighted row is tracked by its key, not by its index.
- The existing shimmer row shows below the received rows while a query has been outstanding for more than 150 ms.
- An engine-suggestion failure is silent: those rows are left out, as in Firefox. A Places failure is already silent (`chrome-bar-places-suggestions.ts`).
- **Row icons (BAR-11):**

| Row | Leading 16px slot | Trailing type marker (16px, muted) |
|-----|-------------------|------------------------------------|
| Heuristic, search | Engine icon, or `codicon-search` | none |
| Heuristic, visit | The origin's favicon, or `codicon-globe` | none |
| Engine suggestion | `codicon-search` | none |
| History | Favicon, or `codicon-globe` | `codicon-history` |
| Bookmark | Favicon, or `codicon-globe` | `codicon-star-full` |
| Open tab | Favicon, or `codicon-globe` | `codicon-browser`, followed by the "Switch to Tab" caption |

- Favicons and engine icons reach the Theia frame **only as `data:` URIs** produced chrome-side from the Places favicon cache and the engine's icon. Any other URL form, or a missing icon, falls back to the codicon. Showing an icon never causes a network fetch (technical ruling: favicons come from Places).
- Every row carries its `source` (`heuristic`, `search`, `history`, `bookmark`, `tab`). Shift+Del and the type marker key on it.

### One-off engine strip (BAR-05)

- The strip sits at the bottom of the dropdown, above the footer, behind a hairline top border. It holds the label "This time, search with:" and one 32×32 button with a 16px icon for each visible engine **except the default**, in `getVisibleEngines()` order. Buttons wrap onto a second line when the strip is too narrow.
- The strip shows only when the text is non-empty and at least one non-default engine exists.
- **Click:** search the typed text with that engine in the current tab. **Ctrl+click or middle-click:** the same search in a new background tab. The choice never changes the default engine, which is the meaning of "This time".
- **Keyboard:** ArrowDown past the last row moves the highlight onto the one-off buttons in order, and then wraps back to the heuristic row. ArrowUp reverses that order. Enter on a highlighted button runs that one-off. A highlighted button gets the item-3 wash.
- Tooltips are rendered by `HoverService` with `pb-chrome-bar-hover`. The dropdown already hides the page (layer policy rule a), so tooltip placement is unconstrained.

### Inline autofill (BAR-07)

- When the caret is at the end, the text has no space and is not composing, and the last keystroke inserted text, the pill completes to the best-matching origin from Places (`moz_origins` via the autofill kind, never raw SQL). An example is `git` → `github.com/`. The completed part is selected (`setSelectionRange`), so the next keystroke replaces it.
- **Enter** opens the completed origin. **Tab** accepts it: the selection collapses to the end, focus stays in the pill, and the dropdown stays open. Tab with no autofill selection keeps its default focus move.
- Backspace or Delete removes the completion, and autofill is suppressed until the next inserting keystroke. Pasting never autofills.
- The heuristic row reads "Visit" with the completed origin as its title.

### Open-tab rows (BAR-06)

- Choosing an open-tab row activates that existing tab (`activateWidget`). The tab is not navigated, so no load starts. The pill then shows that tab's address, and focus goes to its page.
- When the tab lives in another mode's region, the bar switches to it the way a tab-strip click does. There is no extra prompt.

### New-tab targets (BAR-08)

| Gesture | Target | Focus |
|---------|--------|-------|
| Alt+Enter on typed text or the highlighted row | New **foreground** web tab next to the current, joined to the active group | That tab's page |
| Ctrl+click or middle-click on any row (an open-tab row included) | New **background** tab next to the current; the current tab stays selected | The current tab stays as it was; the dropdown closes and the pill reverts to the committed address |

**Decided (autonomous, recommended):** Alt+Enter and Ctrl/middle-click on an open-tab row open
that URL in a new tab instead of switching. The row's caption does not change while a modifier
is held; that live caption change is deferred. The Phase 27 precedent is that middle-click and
Ctrl+click are equal and open in the background.

### Shift+Del (BAR-09)

- Shift+Delete with a **history** row highlighted removes that page through the `PowerBrowserAPI` Places-history kind. This is the first chrome-bar Places write.
- On success, the row disappears and the highlight moves to the next row, or to the previous row when it was the last.
- On failure, the row stays and the Shift+Del failure row is inserted directly under it.
- With any other row highlighted, or none, Shift+Delete is not consumed and keeps the input's default behaviour.
- The kind runs only from this keydown handler, never as a command id (privileged-kind rule).

### Pill context menu (BAR-10)

- Right-click, the context-menu key, or Shift+F10 on the input opens a Theia `.lm-Menu` through `ContextMenuRenderer`, anchored at the pointer, or at the caret for the keyboard. The native input menu is suppressed.
- Items: Cut, Copy, Paste, Paste & Go, separator, Select All.
- Cut and Copy are disabled when nothing is selected. Select All is disabled when the input is empty.
- **Paste and Paste & Go are always enabled.** Enabling them by inspecting the clipboard would be a read without a gesture (Pitfall 13).
- **Paste** inserts the clipboard text at the selection, as typing does: suggestions refresh and autofill is skipped.
- **Paste & Go** replaces the text with the clipboard text and commits it as Enter would. An empty or whitespace-only clipboard does nothing. A read error shows the Paste & Go failure row.
- The clipboard is read only inside these two click handlers. The text is never logged and never pushed.
- Layer policy rule (a) applies: `.lm-Menu` is already in `BLOCKING_LAYER_SELECTOR`. Esc closes the menu and focus returns to the pill. Cut, Copy and Paste leave focus in the pill. Paste & Go moves focus to the page.

### Focus, selection and IME (BAR-11)

- **First click selects all.** A mousedown that gives the pill focus selects the whole text. A drag that starts on that press keeps the dragged selection instead. Later clicks place the caret, and double-click selects a word (stock).
- Keyboard focus (Tab, Ctrl+L, Alt+D, F6) also selects all, which is inherited.
- **IME guard.** While `isComposing` is true, or `keyCode` is 229, the pill handles none of Enter, Tab, ArrowUp/Down, Esc or Shift+Delete, and runs no query and no autofill.
- One query runs on `compositionend`. Composed text is committed only by an Enter that arrives after composition ends.

### Typed text kept per tab (BAR-12)

- Text typed into the pill and not submitted is stored **per tab**, in memory only.
- Switching back to that tab restores the text with the caret at the end. The dropdown stays closed and focus is not moved.
- The draft survives page-initiated navigations in that tab.
- It is cleared by a commit, by Esc's restore step (inherited sequence), and by closing the tab.
- **Decided (autonomous, recommended):** drafts are not persisted across restarts, which matches Firefox.

### Drop on the pill (BAR-13)

- While a link (`text/uri-list` or `text/x-moz-url`) is dragged over the pill, the pill shows the item-7 ring and the copy cursor.
- A plain-text drag gets the copy cursor without the ring, because its content cannot be read until the drop (the 27-UI-SPEC finding).
- On drop, the payload goes through `resolveTypedAddress` and loads in the **current** tab. An http(s) result loads; text that is not an address searches the default engine. Anything else is refused, with `dropEffect: 'none'` for links and the commit failure row for text.
- The dropped text is never inserted into the pill for editing. This matches Firefox, which loads on drop.

### Configured names (BAR-14)

- Every chrome-bar string that names the product uses `{App}`, and every engine mention uses `{engine}`.
- After this phase, `theia/extensions/chrome-bar/src` carries no product-name literal in user-facing text. The two literals left today are rows 1041 and 1047 above.
- The live proof is a sidecar run with a different configured `applicationName`, which must show that name in the failure rows.

### Keyboard summary (pill focused)

| Key | Result |
|-----|--------|
| Enter | Commit the highlighted row (by default the heuristic row) |
| Alt+Enter | The same, in a new foreground tab |
| Ctrl+Enter | Complete `name` to `www.name.com`, then commit |
| Tab | Accept the autofill when it is selected; otherwise the default focus move |
| ArrowDown / ArrowUp | Move through rows, then through the one-off buttons, wrapping |
| Shift+Delete | Remove the highlighted history row |
| Esc | Inherited sequence: close the dropdown, then restore the address and clear the draft, then stop the load |
| F6 / Shift+F6 | Focus the page (inherited) |

The planner confirms that no Theia keybinding intercepts Alt+Enter, Ctrl+Enter or Shift+Delete
while the pill input has focus.

# Phase 33 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** This phase extends the chrome bar contracted in 29-UI-SPEC and 30-UI-SPEC (which
extend 13- and 27-UI-SPEC). Tokens, pill geometry, the 432px result panel, type, colour, the
focus ring, motion, the layer policy, the Esc sequences, the `.pb-chrome-bar-dropdown` portal,
`{App}` / `{engine}` copy rules and the `Browser`-category Actions listing are inherited and are
not re-specified unless they change. It adds, for BMK-01..BMK-06, MENU-03 and SMODE-07:

- the bookmark star at the pill's right end, with its filled state and Ctrl+D
- the star's editor popover (name, folder, Remove, Done)
- the bookmarks toolbar row (Ctrl+Shift+B, live refresh)
- reopen closed tab (Ctrl+Shift+T) and the History submenu (recent pages + recently closed tabs)
- the clear-history range picker panel (Ctrl+Shift+Del, five ranges)
- the full hamburger menu in Firefox order (MENU-03 entries appended to Phase 31's skeleton)
- the Actions-mode rows for the browser actions v1.5 ships, plus the Command-centre-never-sends gate

Hard rules that bind every row below (inherited): no Theia core patch, no Firefox internal outside
`PowerBrowserAPI.sys.mjs`, no custom browser chrome beyond the chrome bar, no internal identifier
in user-facing text, product and engine names from configuration and engine data only, Places
writes only through `PowerBrowserAPI` (never raw SQL, never a second Theia-side writer), the
`127.0.0.1` token cookie exempt from every clear-data kind, no clipboard read without an explicit
user gesture.

Mode: `--auto` (Chris's standing autonomous rule). Every choice not fixed upstream is marked
**Decided (autonomous, recommended)** with its reason.

## Spacing Scale

Inherited unchanged. Values are multiples of 4, except the inherited 12px `md-gap` step.

| Token | Value | Usage in Phase 33 |
|-------|-------|-------------------|
| xs | 4px | Star button gap to the pill edge; gap inside toolbar items; editor field gaps; picker radio gaps |
| sm | 8px | Gap inside rows and menu items (inherited); editor footer button gap |
| md-gap | 12px | Row/menu horizontal padding (inherited); pill right padding (unchanged) |
| md | 16px | Icon slots (16×16, inherited); editor panel padding |
| lg | 24px | Star button 24×24; reset/close hit areas 24×24; toolbar row height 28px is 24 + 4 (see below); submenu group-header row height |
| xl | 32px | Menu/submenu item rows; editor name field height; picker range rows; dropdown panels use the inherited result-row anatomy |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

**New geometry (Decided, autonomous, recommended):**

- **Pill composition (left to right)** becomes: mode button/chip (Phase 30), lock (Phase 31),
  input, **star** (new). Nothing before the input moves; Phase 29's "nothing assumes the lock is
  first" rule extends to the star: nothing assumes the input is last.
- **Star button** (`.pb-address-star`): 24×24, radius 9999px, transparent fill, 16px glyph.
  It sits after the input with the pill's 4px gap on each side, so the 32px pill leaves 3px
  above and below, exactly like the mode button at the other end. Hover takes
  `--color-surface-raised`; focus-visible takes the 1px muted outline inside the pill's own
  accent ring (Phase 30 precedent).
- **Editor panel** (`.pb-chrome-bar-dropdown.pb-bookmark-editor`): anchored to the star —
  `top: calc(100% + 4px)`, `right: 12px`, `left: auto`, `width: 320px`, `padding: 16px`.
  Same max-height rule as the result dropdown. Contents, top to bottom: heading row 24px,
  name field 32px, folder radio list (3 × 32px rows), footer row (Remove left, Cancel/Done
  right, 32px buttons, 8px gap).
- **Bookmarks toolbar** (`.pb-bookmarks-toolbar`): a second full-bleed row in the top panel,
  `height: 28px`, below the 40px chrome-bar row. Items are 24px tall with `padding: 0 8px`,
  `gap: 4px` between favicon and label, radius 4px. Row padding `0 8px`. The chevron (`»`,
  24×24) pins to the row's right end. The top panel grows by exactly 28px while the toolbar
  shows (see the `#theia-top-panel` rule below); the page rect shrinks, nothing overlays it.
- **History submenu / hamburger submenus**: stock `.lm-Menu` items, 32px rows with
  `padding: 0 12px`, `gap: 8px`; group headers 24px caption rows; separators 1px with
  `margin: 4px 0`. Submenu flyouts open to the right of the parent item (stock `.lm-Menu`
  placement, no custom geometry).
- **Clear-history picker** (`.pb-chrome-bar-dropdown.pb-clear-history`): same anchor geometry
  as the editor panel (`top: calc(100% + 4px)`, `right: 12px`, `width: 320px`,
  `padding: 16px`) but anchored to the hamburger button. Contents: heading 24px, five 32px
  radio rows, footer row (Clear + Cancel, 32px buttons).

Exceptions: the 28px toolbar row. Reason: it is 24px content + 4px breathing room inside a
panel row, the same 3-4px relationship the 24px star has inside the 32px pill; no new spacing
token is introduced.

name, port, timeout or raw exception) in user-facing text; `{App}` is `appSubject()`; engine

## Interaction Contract (BMK-01..06, MENU-03, SMODE-07)

### Star and editor (BMK-01, BMK-02)

- **Placement and state.** The star is the last element of the pill, after the input, in every
  PowerBrowser mode including Coding (bookmarking a docs page while coding is the primary
  flow). Unbookmarked: `codicon-star-empty` in muted ink. Bookmarked: `codicon-star-full` in
  text ink. The filled state is visible in all three modes. The star is disabled (dimmed,
  tooltip "You can't bookmark this page") when the active widget is not a web tab or the tab
  has no http(s) page — the same dim-not-removed contract as the nav buttons, so the layout
  never shifts.
- **Bookmarkedness source.** The star follows a per-tab bookmarked flag pushed from chrome
  (Places observer, same push family as the toolbar refresh): navigating, bookmarking or
  removing anywhere updates the star at once. The pill never reads Places directly.
- **Click / Ctrl+D** on an unbookmarked page bookmarks it (Places default folder for the
  one-click path, as in Firefox) and opens the editor; on a bookmarked page it opens the
  editor directly. Ctrl+D works Theia-focused via a chrome-bar keybinding and page-focused
  via a page-focus relay row (D-15, Phase 27 pattern). **In an editor or terminal Ctrl+D
  keeps Theia's meaning** (Monaco add-selection): the KEY-04 ruling — the browser meaning
  wins only while a page or the pill has focus. Clicking the star always works.
- **Editor panel.** A `.pb-chrome-bar-dropdown` portal anchored to the star (geometry above),
  so the page hides while it is open (layer rule a) and no Theia dialog is introduced (D-02).
  Contents: heading, Name text field (prefilled with the page title, selected on open),
  Folder radio list (the three special folders, one level — nested folders and new-folder
  creation are deferred), footer with Remove (left, destructive ink) and Cancel/Done (right).
  Enter in the Name field is Done. Esc closes without saving. Focus returns to the star on
  close (history-menu `onHide` precedent). Remove runs at once with no second confirm and
  closes the panel; the star unfills and the toolbar refreshes.
- **Bookmarks are bookmark rows.** A bookmarked visit keeps rendering as a bookmark row (D-03
  restated): Shift+Del never touches it.

### Bookmarks toolbar (BMK-04)

- **Placement and visibility.** A 28px row rendered by the chrome bar below the pill row in
  the top panel, in every PowerBrowser mode whenever `browser.showBookmarksToolbar` is true
  (D-04: mode-independent). The top panel's min-height grows by 28px while shown via a
  mode-independent rule (`body[data-pb-bookmarks-toolbar="shown"] #theia-top-panel`), so the
  page rect shrinks instead of being covered. Toggle: Ctrl+Shift+B (both focus paths, D-15;
  in an editor/terminal a conflicting Theia binding keeps its meaning per KEY-04 — the
  planner scopes the when-clause), the hamburger Bookmarks submenu check row, and the
  Actions row — all three flip the same preference.
- **Content.** Up to the toolbar folder's items in Places order, each a 24px item with a
  16px favicon (`data:` URI from the Places cache, else `codicon-globe`) and a label capped
  at 160px with ellipsis (chip-label precedent). Click loads in the current tab; Ctrl+click
  or middle-click opens in a new background tab; Alt+Enter opens in a new foreground tab
  (Phase 29 new-tab-target precedent). Right-click opens the item's menu (Open, Open in New
  Tab, Remove — Remove is the editor's remove path, no new code).
- **Overflow (Decided, autonomous, recommended).** A chevron (`»`, 24×24, pinned right)
  opens a portal menu with the hidden items when the row overflows; items never wrap and the
  row never scrolls. Reason: wrapping would change the top-panel height dynamically and move
  the page under the pointer; scrolling hides items with no affordance.
- **Live refresh (D-05).** A chrome-side Places bookmark observer pushes
  `bookmarks-changed`; the toolbar re-reads `listBookmarkFolder('toolbar')`. A bookmark
  added or removed anywhere — editor, submenu, another window — appears or vanishes at once.
  A failed read shows one disabled row with the contracted failure copy; the toolbar never
  shows stale items.

### Closed tabs and history menu (BMK-03, BMK-06)

- **Reopen (BMK-03).** Ctrl+Shift+T (both focus paths, D-15) reopens the most-recently-closed
  row from `tabs.sqlite` (`closed_at` non-null, D-06) in a new web tab next to the opener and
  restores its session history through `shellArmWebTabHistory` (D-07, the 27-02 path). With
  no closed rows, the command is a no-op and the History submenu's reopen row is disabled.
  Open rows (`closed_at` null) never appear and are never deleted by any clear path
  (prune semantics, D-15 discretion).
- **History submenu (D-08).** A submenu of the hamburger (not a second chrome-bar button),
  in this order: **Reopen Closed Tab** + hint, separator, **Recently closed tabs** header +
  up to 10 closed rows (most recent first; title or address, one line each), separator,
  **Recent pages** header + up to 10 recent Places visits, separator,
  **Clear Recent History…** + hint. Choosing a closed row reopens it with history (same path
  as Ctrl+Shift+T); choosing a recent page loads it in the current tab (Alt+Enter / Ctrl /
  middle-click follow the Phase 29 new-tab targets). An empty section shows its contracted
  "No …" disabled row. Closed rows come from the `tabs.sqlite` read path (sessionstore merge
  at startup only, D-06); recent pages come from the existing `searchPlaces` history read.

### Clear history (BMK-05)

- **One kind, five ranges (D-09, D-09b).** One privileged `clearHistory` store kind (event-handler
  only, never a command id) fans out chrome-side to Places history (via
  `PlacesUtils.history.removeVisitsByFilter({beginDate,endDate})` range deletes — never `Sanitizer` at all, whose `showUI`
  path needs `gDialogBox`, absent in the `powerbrowser:main` shell),
  `tabs.sqlite` closed rows, thumbnails, saved pages and web-tab history. The range picker offers **Last hour**,
  **Last 2 hours**, **Last 4 hours**, **Today**, **Everything** — Firefox's set minus the
  site-specific rows this tree has no stores for. The `127.0.0.1` token cookie is exempt
  from every range (planted-clear check reused from Phase 31). Open tabs survive every range.
- **Picker panel (D-10).** The star-editor portal pattern, anchored to the hamburger button
  (same geometry as the editor panel). Heading, five radio rows (default Last hour), the
  contracted footnote naming the fan-out, footer with **Clear** (destructive ink) / Cancel.
  Enter is Clear; Esc is Cancel; focus returns to the opener. The panel **is** the
  confirmation — no second dialog. On success it closes and the History submenu, toolbar
  badges and address-bar history rows all reflect the clear at once; on failure the
  contracted failure row shows in the panel.

  4. **Bookmarks** › (Phase 33 submenu: Bookmark This Page, Show Bookmarks Toolbar check,
     up to 10 recent bookmarks)
  5. **History** › (Phase 33 submenu per BMK-06 above)
  6. **Downloads** (Phase 33 row; opens the Phase 32 downloads panel; disabled with no web
     tab history — dimmed, never removed)
  7. separator
  8. **Print…** (Phase 33 row; Phase 32 print command)
  9. **Save Page As…** (Phase 33 row; Phase 32 save command)
  10. **Find in Page…** (Phase 33 row; Phase 32 find command)
  11. **Zoom** › (Phase 33 submenu: Zoom In / Zoom Out / Reset / current-level row; Phase 32
      zoom command)
  12. **Edit** › (Phase 33 plan 05 submenu, PAGE-09 carried from Phase 32 by the 2026-10-31
      coordinator ruling: Undo, Redo, Cut, Copy, Paste, Select All, greyed from the page's live
      enablement; where Firefox's hamburger last carried its Edit row, after Zoom)
  13. **Full Screen** (Phase 33 row; `powerbrowser.chrome-bar.full-screen` command id calling
      `ChromeStoreClient.fullScreen()` from the widget handler, chrome toggles `window.fullScreen`
      per `upstream/browser/base/content/browser-commands.js:567-569` behind the same
      command id until the Phase 35 fullscreen path lands, so the id is stable — D-14/D-14b;
      the `fullScreen` store kind is classed `window-chrome` so the command id may reach it)
  14. separator
  15. **More Tools** › (Phase 33 submenu: Page Source, Reader View, Page Developer Tools —
      only rows whose Phase 32 command exists)
  16. **Help** › (Phase 33 submenu: Get Help with the configured help URL, About {App})

- **Omissions (Firefox rows deliberately absent):** New Private Window, Tab groups, AI window,
  Report Broken Site, Sync/account rows — per REQUIREMENTS Out of Scope and the gap list.
  No Library window (`about:places`), no import-from-browser, no warn-on-close (deferred
  ideas, no v1.5 requirement).
- **Submenu behaviour (Decided; amended by owner ruling 2026-11-05, 33-UAT test 7).** Submenus
  open on hover after stock Lumino's 300ms delay and on Right-arrow / Enter when the parent row
  is highlighted; Esc steps back one level; Left-arrow on a submenu's first item returns to the
  parent. The original 200ms target would need an edit to `@lumino/widgets`, which hard rule 1
  forbids, so the shipped 300ms stands. It serves the same intent as the 500ms history hold
  (avoid accidental opens) at menu-traversal speed. All menu layers are blocking layers, so
  the page hides while any menu is open (inherited rule a).
- **Enablement.** Every row that needs a web tab is dimmed-not-removed without one, tooltips
  retained. New Window, Bookmarks, History, Help and the Phase 31 rows are always enabled.

### Actions mode (SMODE-07)

- **Rows.** Actions mode lists whatever `Browser`-category commands exist at enumeration time
  (D-13, FEATURES dependency note): after this phase that is Back, Forward, Reload, New Tab
  (Phase 30), the four new commands above, and every Phase 32 browser action (Print,
  Downloads, Clear Recent History duplicates none — one command id, two surfaces). Missing
  Phase 32 commands simply have no row yet; each later phase adds rows by registering
  commands, with no address-bar change. Row anatomy, badges and Enter/click behaviour are the
  inherited Actions contract.
- **Command-centre guarantee (second half of SMODE-07).** Command centre never sends typed
  text to a search engine: the MODE_SENDS `command-centre` row stays all-false and this
  phase adds no exception. New privileged kinds (`clearHistory`, bookmark writes) and

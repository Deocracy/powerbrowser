C10' Terminal keys (D-32). Derived from the reserved PAGE_KEYS rows in powerbrowser/shell/powerbrowser.js:
  - shell keys = reserved rows with a letter key (accel+T, accel+W: ctrl+t, ctrl+w). ORCA_TERMINAL_PASSTHROUGH_KEYS equals this set; the rows stay KeybindingRegistry.PASSTHROUGH_PSEUDO_COMMAND with when ORCA_TERMINAL_KEYS_WHEN on the scoped key powerbrowser.orcaTerminalFocus. Theia t<n> terminals already pass these to the shell (Theia's own terminalFocus passthrough rows; 64-04-SUMMARY Observations).
  - switch keys = reserved rows with a keycode (ctrl+tab, ctrl+shift+tab, ctrl+pageup, ctrl+pagedown). No PowerBrowser passthrough row names one. ctrl+tab and ctrl+shift+tab are Theia core's CommonCommands.NEXT_TAB and PREVIOUS_TAB bindings (common-frontend-contribution.js). chrome-bar-keybindings.ts adds ctrl+pagedown to CommonCommands.NEXT_TAB.id and ctrl+pageup to CommonCommands.PREVIOUS_TAB.id: literal ctrl, no when clause. Each switch key's Theia command equals the command of the switch key whose PAGE_SHORTCUTS action body is the same (nextTab and nextTabPage both step +1; prevTab and prevTabPage both step -1).
  - close key = the closeTab row's key with shift added (ctrl+shift+w). chrome-bar-keybindings.ts binds it to CommonCommands.CLOSE_TAB.id (core.close.tab, which closes the current tab in any area through widget.close(), so a hosted Orca pane goes through Orca's own close and confirmation, P64-11): literal ctrl, no when clause. It is a Theia-focus key: a focused web page keeps Ctrl+W (the reserved closeTab row) and receives Ctrl+Shift+W itself, and no PAGE_KEYS row is added (D-32 is about terminals; the SUMMARY records this).
  - Commands are named through the imported CommonCommands consts from @theia/core/lib/browser, never re-spelled id strings (gui06-chrome-bar-commands' rule). verify-shortcut-relay's rule 12 reads only *_COMMAND_ID bindings, so it is unaffected; it must stay green.

C13 Hosted terminal shortcut policy (new, D-32). The overlay entry keeps useAppStore's settings.terminalShortcutPolicy at 'terminal-first' in PowerBrowser's hosted document only: one useAppStore.setState when bootstrap installs the services root, and a useAppStore.subscribe that re-applies it whenever a settings object arrives with another value (hydration and host refreshes replace settings). It never calls Orca's settings update actions (updateSettings, updateSettingsOrThrow or the persistence helpers), so orcad's persisted settings, Orca's own web client paired to PowerBrowser's orcad, and Orca desktop keep their own policy. Mechanism, from the pinned source: TerminalPane reads settings through use-terminal-pane-store-bindings.ts:29 (useAppStore(store => store.settings)) and passes settings.terminalShortcutPolicy to useTerminalKeyboardShortcuts (use-terminal-pane-global-listeners.ts:91), which installs window-capture keydown listeners (terminal-keyboard-hook.ts) whose matching goes through keybindingIsActiveInContext (orca/src/shared/keybindings/effective.ts). Under 'terminal-first', a terminal context drops every shortcut that is neither terminal-scoped nor allowInTerminal, plus TUI_CONFLICT_ACTIONS, which hold terminal.closePane (Mod+W). Ctrl+Tab and Ctrl+PageUp/PageDown are tab-scope rows that TerminalPane's resolver never maps (terminal-shortcut-policy.ts), so they fall through to Theia's document-capture keybinding dispatch.

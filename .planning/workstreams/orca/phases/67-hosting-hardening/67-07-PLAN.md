Root cause of WINDOWS 45 (read in Orca's source at the pin):
  - pb-session-pairing.ts pairSessionOnly saved the new pairing through saveStoredWebRuntimeEnvironment only.
    Orca's preload keeps its own webRuntimeState.activeEnvironment and webRuntimeState.activeClient
    (web/preload-api/web-runtime-session.ts); after repair() both still named the replaced pairing.
  - The open client holds an ephemeral session device key (web-runtime-credential-source.ts sessionPlan). Its row
    died with the killed orcad (P65-17), so the restarted orcad refuses it; deviceRevoked calls forgetPairing, and
    credentialFor's forgetPairing (isActivePairing compares against the stale active environment: true) runs
    clearStoredWebRuntimeEnvironment, which also clears the new session pairing.
  - The next repair() reads no previous environment, so createStoredWebRuntimeEnvironment
    (web-runtime-environment.ts:131-149) mints web-<uuid>: "a new one strands its sessions (#11574)". Subscriptions
    then log "Unknown Orca runtime environment: web-<uuid>" (measured in .mozbuild/p67-06/dbg6.log).
  - Orca's own in-browser path for a new pairing, addFromPairingCode (web-runtime-environments-api.ts:50-66), closes
    the active clients and sets webRuntimeState.activeEnvironment; repair() did neither.
Second effect, measured live in 67-07: once the client really changes pairing, Orca's store hydrates again and its
pane list is empty for about 10 s; OrcaPaneObserver disposed every hosted widget on it and re-created them
renumbered (term1 to term2), the case P65-35 holds after a reload.
Landing (WINDOWS 46): AppWorkspaceShell.tsx renders Landing when activeView is 'terminal', no pending creation and
activeWorktreeId is null. Orca sets it null from the page when the last tab of the active worktree closes
(terminal-tab-actions.ts, workspace-emptied-reaction.ts), on workspace sleep, and for folder or WSL removal. The tab
close button carries data-tab-close-button="true", which Orca keeps for E2E (SortableTab.tsx). A running process
asks first (CloseTerminalDialog.tsx, "Stop and Close").
</interfaces>

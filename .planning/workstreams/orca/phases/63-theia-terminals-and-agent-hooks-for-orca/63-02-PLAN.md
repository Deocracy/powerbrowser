Names and files:
- Environment names: ORCA_EXTERNAL_PTY_ENDPOINT (orcad; value the absolute path of <bridge dir>/endpoint.json; OrcaEnv exports it as ORCAD_PTY_ENDPOINT_SWITCH and lists it in ORCAD_FIXED_ENV_NAMES) and POWERBROWSER_ORCA_PTY_DIR (Theia backend; value the absolute bridge directory; captured and deleted at module load by token-gate's powerbrowser-env.ts like every POWERBROWSER_* key).
- Bridge directory: OrcaEnv.ptyBridgeDirFor(dataRoot, getEnv, platform), platform in Node's spelling (OrcaEnv.nodePlatform maps the boundary's AppConstants value: linux to linux, macosx to darwin, win to win32), with dataRoot = OrcaEnv.dataRootFor(profileDir) = <ProfD>/powerbrowser-orca (the real data root, never its alias). On linux and darwin it is OrcaEnv.aliasPathFor(dataRoot, getEnv) followed by "-pty" ($XDG_RUNTIME_DIR/pb-orca-<12 hex>-pty, else $HOME/.cache/pb-orca-<12 hex>-pty; never under /tmp); on win32 it is <LOCALAPPDATA>\pb-orca-<12 hex>-pty when LOCALAPPDATA is an absolute drive path; otherwise null. The 12 hex are the start of SHA-256 of dataRoot in every case. On linux and darwin the directory has mode 0700 and is owned by the current uid, and a directory with any group or other permission bit is refused by the Theia bridge and by the orcad client.
- Listen path: orcaPtyListenPath(dir, platform) in theia/extensions/orca-terminals/src/node/orca-pty-paths.ts (node:crypto and node:path only): on linux and darwin <dir>/bridge.sock, refused naming the limit when its UTF-8 length exceeds 107 bytes on linux or 103 on darwin (sun_path less the terminator); on win32 \\.\pipe\orca-pty-<first 12 hex of SHA-256 of dir>. endpointFileFor(dir, platform) joins dir and endpoint.json with that platform's separator.
- Files in the bridge directory: endpoint.json (Theia bridge; 0600 on linux and darwin; written to a temporary name and renamed after the server listens; a JSON object with exactly the keys version (integer 1), path (the listen path) and token (64 lowercase hex characters from 32 random bytes)); bridge.sock on linux and darwin (Theia bridge; Unix socket; 0600); orcad-data-root (OrcaService; 0600; one line: orcad's ORCA_USER_DATA value followed by a newline); claude-wrapper (orca-agents backend; 0700; POSIX sh launcher); claude-wrapper.log (the wrapper; 0600; appended).

Wire:
- Newline-delimited JSON over a node:net connection to endpoint.json's path (net.connect({ path }) and net.createServer().listen(path) on every platform): one UTF-8 JSON object per line, every object has a string type. A line longer than 16 MiB closes the connection. Unknown types are dropped and counted, never echoed. Both sides validate fields and drop a frame whose fields have the wrong type.
- Client (orcad) to bridge: hello {version, token} (must be the first frame; a different first frame, a wrong token or a different version gets error {code} and the connection closes); spawn {id, file, args, cwd, cols, rows, env, termName}; write {id, data}; resize {id, cols, rows}; kill {id, signal?} (signal is a name such as "SIGHUP"; absent means node-pty's default); pause {id}; resume {id}; close {id} (the client released the handle; the bridge kills the process if it is alive).
- Bridge to client: ready {version}; spawned {id, pid, ptsName, name} (name is the Theia identity o<n>); spawnFailed {id, message} (message names no env value); data {id, data}; exit {id, exitCode, signal} (numbers or null); resized {id, cols, rows} (a resize made from the Theia side); error {code}.
- Field rules: id is a client-chosen string unique per connection; file and cwd are absolute paths; args is an array of strings; env is an object of string values and is the PTY's entire environment (the bridge adds and removes nothing); cols and rows are integers from 1 to 4096.
- Exported sets, identical literals on both sides: Theia side theia/extensions/orca-terminals/src/common/orca-pty-protocol.ts exports ORCA_PTY_PROTOCOL_VERSION (1), ORCA_PTY_CLIENT_MESSAGES and ORCA_PTY_SERVER_MESSAGES (frozen arrays of the names above); overlay side external-pty-bridge.ts exports EXTERNAL_PTY_PROTOCOL_VERSION, EXTERNAL_PTY_CLIENT_MESSAGES and EXTERNAL_PTY_SERVER_MESSAGES. orca-pty-contract (lane p63-01) compares versions and both sets.
- Lifecycle: one connection per orcad, opened on the first spawn; endpoint.json is re-read at every connect. The first connect retries reading the file and connecting for up to 10000 ms, then fails the spawn; it never falls back to node-pty. When the connection drops, the client fires onExit for every live PTY and reconnects on the next spawn; the bridge kills every live PTY of that connection after a grace of 5000 ms and keeps their tabs open showing the exit (P63-10).
- Flow control: the bridge pauses a PTY while the client has paused it or while the socket's write buffer is full, and resumes on drain.
- Logging: neither side logs a frame payload, an env value or the token; log lines name message types, ids, pids and o<n> names only.
- Names: the bridge mints o<n> with the lowest index not used by any entry minted in this backend lifetime nor reserved by a frontend (reserveNames), so a restored dead tab's name is never reused (P63-06).

Bridge core JavaScript API (lane p63-02 implements it; lane p63-01's bridge host imports it):
- theia/extensions/orca-terminals/lib/node/orca-pty-bridge-core.js (CommonJS, compiled from src/node/orca-pty-bridge-core.ts) exports createOrcaPtyBridge(options) and nodePtySpawner(nodePty).
- options: { dir, spawnPty, onOpened?, log?, graceMs? } (graceMs defaults to 5000). Returns { start(): Promise<{ listenPath, endpointFile }>, stop(): Promise<void>, entries(): Array<{ name, pid }>, reserveNames(names: string[]): void }. start() takes the platform from process.platform, creates dir (mode 0700 on linux and darwin) when absent, rejects naming the mode when an existing dir grants group or other access on linux or darwin, and listens on orcaPtyListenPath(dir).
- spawnPty(request) receives { file, args, cwd, cols, rows, env, termName } and returns a PtyHandle { pid, ptsName, write(data), resize(cols, rows), kill(signal?), pause(), resume(), onData(cb(data)), onExit(cb({ exitCode, signal })), onResize?(cb({ cols, rows })) }; extra fields on the handle (Theia's processId) are passed through untouched. onOpened({ name, pid, handle }) is called after each successful spawn.
- nodePtySpawner(nodePty) returns a spawnPty that calls nodePty.spawn(file, args, { name: termName, cols, rows, cwd, env }).

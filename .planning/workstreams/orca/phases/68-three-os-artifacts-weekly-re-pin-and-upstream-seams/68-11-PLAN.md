<objective>
Gap closure for 68-09. The pre-installed Claude agent SDK extension can be uninstalled, and the
68-09 record keeps it out for good, so today an uninstall is permanent. On 2026-11-15 the owner
chose "Add reinstall now" over shipping v1.7 without one. This plan adds the smallest correct
affordance: one command, offered only while the extension is absent, that redeploys the bundled
copy from the installed PowerBrowser package. The rule "an uninstall is not undone automatically"
stays true; the reinstall happens only on the user's explicit action.

Output: the reinstall service and command in @powerbrowser/bundled-extensions, the copy table, the
README's next step, the new check legs and plants, 68-11-SUMMARY.md.
</objective>

Tree facts this plan relies on (Theia 1.76, read in node_modules):
- PluginVSCodeDeployerParticipant pushes the deployment folder as a local-dir user entry at every
  start; the local-dir resolver deploys each child, skipping dot-prefixed names.
- PluginServerImpl.install(entry, type) runs PluginDeployerImpl.deploy, which resolves, deploys and
  fires onDidDeploy. PluginDeployerHandlerImpl.deployPlugin skips an id already deployed this session
  and calls markAsInstalled, which clears an in-session uninstall mark. The uninstalled set is in
  memory only.
- PluginDeployerHandlerImpl.uninstallPlugin removes the source folder before it marks the plugin
  uninstalled, and HostedPluginServerImpl forwards that change to the frontend as onDidDeploy, so
  HostedPluginWatcher.onDidDeploy fires after an uninstall too.
- The 68-09 seed copies <pluginsDir>/.user/<id> into <THEIA_CONFIG_DIR>/deployedPlugins/<id> through a
  temporary sibling and a rename, and records { id: version } in backend-settings key
  bundledExtensions.seeded.

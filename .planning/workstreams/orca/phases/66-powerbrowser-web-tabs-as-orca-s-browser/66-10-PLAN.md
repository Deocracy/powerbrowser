<interfaces>
Read in the pinned tree (upstream/, 153.5.0):
  - Every page clipboard write is gated by transient activation only: nsContentUtils::IsCutCopyAllowed
    (nsContentUtils.cpp:8450-8458) for document.execCommand copy/cut (Document.cpp) and Clipboard::Write
    (Clipboard.cpp:693). An agent's trusted click supplies the activation. The parent writes whatever arrives
    (ContentParent::RecvSetClipboard, kCClipboardCID), and nsBaseClipboard has no per-window hook. No sandbox flag,
    BrowsingContext field or permission refuses it per context, so the wall is content-side.
  - nsCopySupport::FireClipboardEvent (nsCopySupport.cpp:775-): a copy or cut whose event is cancelled with an empty
    clipboardData writes nothing; a cancelled paste pastes nothing. execCommand copy/cut, key and menu commands and
    middle-click paste all go through it.
  - JSWindowActor events (JSWindowActorProtocol.cpp:111-134, :262) default to the default group; a capturing listener
    on the chrome event handler runs before any page listener. DOMWindowCreated fires before any script of a new
    window. No matches means every URI; allFrames admits frames; messageManagerGroups admits the agent group only.
  - GroupActorChild may not use Cu. (check-internals-boundary.sh ACTOR_CHILD_PATTERNS), so no exportFunction: the
    replacement methods are the page's own Promise.reject bound to a page DOMException (Function.prototype.bind run
    in the page realm through wrappedJSObject), so no chrome function reaches the page.
  - Agent keys come from nsITextInputProcessor with no native key event, so GTK's native bindings never run for them
    (NativeKeyBindings.cpp:304-307); only Gecko's shortcut tables (ShortcutKeyDefinitions.cpp) map them to commands.
  - Residual, recorded not closed: on Linux, Gecko's AutoCopyListener copies a selection made by mouse-up, select-all
    or key into the PRIMARY selection (nsFrameSelection.cpp:3370-), with no per-document switch (a Gecko patch or the
    global clipboard.autocopy pref would be needed). It writes no page-chosen data without the agent's own selection.
  - permissions.isolateBy.userContext: StaticPrefList.yaml:16999-17002 (default false, mirror always), read by
    PermissionManager::MaybeStripOriginAttributes (PermissionManager.cpp:4456). dist/bin's firefox-branding.js is a
    symlink into generated/branding/dev, so a regenerated file needs no build.
Error code: browser_command_unavailable (D-35's reason).
</interfaces>

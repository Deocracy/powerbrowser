<interfaces>
C3-66 (bundle API, pb-pane-mount.tsx), names added to orca-pane-entry's C3_EXPORTS:
  - addBrowserPage(worktreeId, browserPageId): boolean. The environment is the session-only pairing's
    (readStoredWebRuntimeEnvironment().id: this client's settings carry no active environment). It writes the
    records createBrowserTab draws, in the shape stageWebRuntimeBrowserTab stages a client-hosted page:
    buildBrowserPage (page id = browserPageId) and buildWorkspaceFromPage; one useAppStore.setState of
    browserTabsByWorktree, browserPagesByWorkspace and browserTabOpenView(..., { activate: false });
    setRemoteBrowserPageHandle(page.id, { environmentId, remotePageId, staged: true, stagedClientHosted: true });
    createUnifiedTab(worktreeId, 'browser', { entityId, label, executionHostId, activate: false }). False when a
    row for the page exists or there is no pairing. createBrowserTab itself is not called: its
    assertManagedBrowserMaterializationAllowed gate refuses a paired web client whose runtime lacks the
    screencast capability (measured: "Managed browser tabs are unavailable because the paired runtime does not
    support browser streaming."), and PowerBrowser's orcad has no engine; the page is PowerBrowser's.
  - removeBrowserPage(browserPageId): discardStagedWebRuntimeBrowserTab on the row (handle first, then
    closeBrowserTab with reason 'cleanup').
  - selectBrowserPage(browserPageId): boolean. Orca's focusBrowserTabInWorktree on the row's worktree, the
    store action a tab switch --focus ends in on Orca's desktop. Used by checks only (P64-10 rule).
Host (pb-browser-host.ts): commandResult for a completed createPage with a workspaceId calls addBrowserPage;
for a completed closePage calls removeBrowserPage; userClosedPage calls removeBrowserPage before its
browser.tabClose. It reaches the bundle through globalThis[Symbol.for(ORCA_PANES_MODULE_KEY)]; absent (Node
probe) it does nothing, and a row failure never touches the host's result.
Reveal tracker (orca-browser-dispatch.ts, P66-09 restated by D-34): a noteCreated mark is cleared without a
reveal by the page's first listed record. The row is PowerBrowser's own, added in the background after the
createPage it served, so no creation activation follows it; the 66-02 window of two inactive lists would
swallow the user's first selection.
Measured facts this plan relies on (66-07 probes): orcad's session.tabs.list lists no client-hosted page
before or after a CLI tab switch, with or without --focus, so no CLI switch reaches a client store; the main
area's current tab (getCurrentWidget('main')) changes on a reveal while the focus tracker's currentWidget
stays null on this host.
</interfaces>

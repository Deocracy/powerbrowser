whose opener is an agent overlay is refused on every open path, so nothing an agent page opens leaves the agent
isolation. Purpose: the privacy paragraph's "An agent never reaches your other tabs or your browser windows" holds.

</objective>

<interfaces>
Open paths into the parent, found by search (installNewWindowReceivers, ContentParent::CommonCreateWindow,
nsWindowWatcher, ClickHandlerParent, every openStockTab caller):
  - browserDOMWindow.createContentWindowInFrame / openURIInFrame -> adoptContentWindow (window.open, target=_blank,
    form target diverted to a tab, print browser). A null makes ContentParent fall through to OPEN_NEWWINDOW
    (ContentParent.cpp:5505-5508); a failure refuses (5509-5511).
  - browserDOMWindow.createContentWindow / openURI -> adoptInProcessWindow (in-process openers; null opens a stock
    window).
  - window.openLinkIn -> adoptLinkIn (ClickHandlerParent.contentAreaClick: middle-click, modified click, Enter on a
    link; every where, "window" to openStockTab).
  - OPEN_NEWWINDOW (window.open with features, shift modifier, document PiP): ContentParent calls
    nsWindowWatcher::OpenWindowWithRemoteTab without asking chrome; no chrome receiver exists, so the content-side
    SANDBOXED_AUXILIARY_NAVIGATION (nsWindowWatcher.cpp:982) is the wall.
  - openStockTab's other callers (the Theia openStockTab kind, the CLI single-instance handler, extensionInstallSite,
    adoptFallback) take no page opener; adoptFallback runs only for a pending overlay, which an agent never gets.
Error code: browser_command_unavailable (Orca's BrowserErrorCode is a closed union in a tracked Orca file).
</interfaces>

# Phase 66 Plan 04: Page snapshot for Orca agents Summary

`browser.snapshot` now works in the PowerBrowserAgent child. It builds an accessibility-style tree from the DOM, through Xrays, without Gecko's accessibility service and without XPCOM. The output uses agent-browser 0.39.4's text grammar, its `refs` object and its `full`, `unchanged` and `delta` replies. Refs bind to live nodes through a per-page WeakRef table, and every element-targeted row resolves `@eN` through it. The references come from running Orca's pinned agent-browser binary against Chromium, and a live row compares PowerBrowser's output with them structurally.

## What was built

- **Child, `GroupActorChild.sys.mjs`.**
  - `agentFind(actor, target, staleIsGone)` replaces the selector-only lookup. `@eN` or `eN` reads the page's ref table. An unknown ref answers `browser_ref_not_found`. A ref whose node is gone, or is no longer in this document (`document.contains`), answers `browser_stale_ref`. A wait gets `null` for a stale ref, because "gone" is the answer it waits for. Any other string is a CSS selector.
  - `agentElement` and `browser.wait` both go through `agentFind`, so every element-targeted arm resolves refs: click, dblclick, hover, drag, focus, fill, clear, check, select, selectAll, scrollIntoView, wait and exec's read/get/is.
  - The `browser.snapshot` arm calls `agentSnapshot`, appended after the classes. It handles the options interactive, compact, depth, selector (a ref works too) and urls, plus delta and full.
  - The ref table is `actor.snap`, keyed by `windowGlobalChild.innerWindowId`. A new document starts with an empty table and no baseline. Refs are never recycled within a page, and a node keeps its ref across snapshots.
  - A result over 768 KiB answers `browser_error`. The size goes to the console only.
- **Generator.** `gen-orca-snapshot-fixtures.mjs` serves the fixture html on a loopback port. For each page in the manifest it runs `snapshot`, `snapshot -i`, a `snapshot --delta` baseline, `eval pbChange()` and a second `snapshot --delta`, and writes `<page>.json` and the manifest version. It runs the binary asynchronously, because a blocking call stalled its own server. If a step fails, it names the step and always closes the agent-browser session.
- **Fixtures.**
  - `form.html` is the spike page plus click counters and `pbChange()`, which adds one button. Its reference shows 13 refs, and the change gives a `delta`.
  - `nav.html` has headings at three levels, a nav list of links, a table with a header row, closed and open details, and an ARIA tablist. Its `pbChange()` removes a list item and adds a button. Its reference shows 15 refs, and the change gives a `delta` with a remove and an add.
- **Live row.** `verify-orca-browser-snapshot-live.mjs` checks each fixture against the reference for the full and interactive forms:
  - the grammar on every line;
  - the ref'd (role, name) multiset;
  - the level/checked/expanded/selected tokens per ref'd node;
  - the delta kind after `pbChange()`;
  - ref survival, plus a post-change multiset of surviving and added nodes;
  - `click @eN` on every button and tab ref moves exactly that element's counter;
  - a removed node's ref answers `browser_stale_ref` in the error message (Pitfall 8).

  `--fixtures` is the quick version-pin row. `--self-test` plants 12 faults.

## Role and name rules as built

- **Roles.** An ARIA `role` token is used first when it is a known role; `none` and `presentation` hide the element but keep its children. Otherwise the implicit HTML role applies:
  - a/area[href] link; button; input by type (button types are button, checkbox, radio, range is slider, number is spinbutton, search is searchbox, `list` makes a combobox, anything else is textbox; hidden is skipped); textarea; select (combobox, or listbox when multiple or size > 1); option;
  - h1-h6 heading; ul/ol/menu list; li listitem; table, thead/tfoot rowgroup, tr row, td cell (gridcell in a grid), th columnheader (rowheader with scope=row);
  - details/fieldset/optgroup group; summary DisclosureTriangle; header banner and footer contentinfo outside article/aside/main/nav/section; section region when named;
  - nav, main, form, p, img (not alt=""), hr, dialog, figure, article, aside, output, progress, meter, blockquote.

  Elements without a role are transparent: their children move up a level.
- **Names.** aria-labelledby, then aria-label, then the input button value or default, then image alt, then associated labels (without the control's own text), then legend/figcaption/caption, then alt. For name-from-content roles (button, link, heading, cells, option, tab, checkbox, radio, switch, menuitems, treeitem, tooltip, DisclosureTriangle) the visible text comes next. title and placeholder are the last fallback.
- **Attribute tokens.**
  - `level` for headings and list items (list nesting depth);
  - `checked=true|false|mixed`;
  - `expanded` for summary, aria-expanded and select comboboxes;
  - bare `selected`;
  - bare `disabled`;
  - `ref=eN`, then `url=` with `--urls`.
  - The value suffix `: <value>` is used for select and text fields (never passwords).
- **Hidden content.** These are skipped: `aria-hidden=true`, no box (display:none, closed details content), and visibility:hidden (the element itself; its children are still walked). Options inside a select are exempt from the box test.
- **Text.** `StaticText "..."` lines are emitted in the full form. They are left out inside ref'd name-from-content nodes and inside labels that label a control.

**Reference (role, name) not reproduced:** none on the ref'd nodes. Only lines without a ref differ from the references: Chromium's `LabelText`, `MenuListPopup` and `ListMarker`, and some `StaticText` children. G9 already says these cannot be reproduced byte for byte, and the live row does not compare them. **No BLOCKER.**

Pre-build evidence: the arm's code was run as page script in the host's stock Firefox over WebDriver BiDi, against both fixtures (a scratchpad harness, not committed). The live row's own verdict function `pageVerdict` passed on both pages: full, interactive, ref set, tokens, delta kind `delta`, survival and post-change set. `@e3` resolved, a removed ref answered `browser_stale_ref`, and an unknown ref answered `browser_ref_not_found`. This was page script, not the actor child through Xrays. Only the coordinator's live run proves the child itself.

## Deviations from Plan

1. **[Rule 3 - Blocking] The generator runs the binary asynchronously.** The first run timed out at `open`, because `execFileSync` blocked the process that serves the fixture page. Fixed in Task 1 before commit.
2. **Task split.** Task 1's commit already holds the ref table, the resolver and the delta logic, because the tracer snapshot needs refs and its JSON shape. It also holds every verdict of the live row. Task 2 changed the baseline to one per page (Orca's snapshot help: "Each page keeps one --delta baseline ... different flags return the whole tree again"), added the nav fixture and regenerated both fixtures. No throwaway code was written to keep the tasks apart.
3. **Fixture instrumentation.** The click counters are one document-level capture listener in a fixture script, not `onclick` attributes. The form's submit is prevented so a click does not navigate. The references show this adds no clickable hint.
4. **`exec get count` keeps `querySelectorAll`.** It counts selector matches and is not an element target, so it does not go through `agentFind`. No other selector parser exists in the child.

## Known limits

- The delta size rule is a documented shortcut, not agent-browser's own (see decisions). A large change can answer `full` where agent-browser would answer `delta`, or the other way round. The fixtures' changes are small and agree.
- Accessible names follow a reduced accname: no CSS-generated content, and no embedded-control values inside names.
- Same-origin iframes are not walked; agent-browser walks them.
- The `-s` selector option returns the refs of the scoped subtree only. agent-browser's refs object lists the whole page's refs.
